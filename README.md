# 企业信息自动查询截图

输入**单个企业名称**，或从 Excel / CSV **批量读取**，自动在 **国家企业信用信息公示系统**、**企查查**、**爱企查** 依次查询，并截取企业详情页的**整页长图**（截图可关闭）。

基于 Chrome / Edge 的浏览器扩展（Manifest V3），无需服务端。

## 功能特性

- **单个查询**：直接输入一个企业名称（回车即可）立即查询，无需准备文件
- **批量导入**：支持 `.xlsx` / `.xls` / `.csv`，可指定表头与名称所在列
- **自动填入并查询**：自动定位搜索框、填入企业名称、点击查询
- **自动进入详情**：自动识别并打开第一条搜索结果
- **自动提取企业信息**：进入详情页后提取页面全部字段，任务结束后汇总导出为 Excel（需在「3. 导出与截图」中勾选，默认关闭）
- **截图可选**：可关闭截图开关，只执行查询不生成图片（同时也就不再需要调试接口）
- **整页长图截图**：先自动滚动到底触发懒加载，再截取完整页面（单张上限 16384 像素）
- **验证码 / 登录暂停**：检测到验证码或登录页时暂停，人工处理完成后自动续跑
- **规范命名归档**：按站点分目录，按「企业名 + 时间戳」命名，同名不覆盖
- **任务可控**：按企业分组展示各站点状态，支持暂停、停止、只重试失败项
- **失败自诊断**：任务失败时自动输出页面结构信息，便于站点改版后快速校准

## 环境要求

- Chrome / Edge **116 及以上**
- 无需安装任何依赖（Excel 解析库已内置在 `lib/`）

## 安装

1. 克隆或下载本仓库

   ```bash
   git clone https://github.com/edrfe/Automated-query-screenshot.git
   ```

2. 打开扩展管理页：Edge 输入 `edge://extensions`，Chrome 输入 `chrome://extensions`
3. 打开右上角「开发人员模式」
4. 点击「加载解压缩的扩展」，选择本仓库目录（即包含 `manifest.json` 的目录）
5. 建议点击工具栏的拼图图标，把扩展固定到工具栏

> **注意**：修改任何代码或文件后，都必须回到扩展管理页点击本扩展的「刷新」按钮才会生效。

## 使用

1. 点击工具栏的扩展图标，打开侧边栏
2. 在「1. 企业名称来源」选择查询方式：
   - **单个查询**：直接在输入框填入企业名称，按回车或点「查询」立即执行
   - **批量查询**：选择 Excel / CSV，设置「首行是表头」，再选择「名称所在列」
3. 在「2. 查询站点」勾选需要查询的站点（默认不勾选）
4. 在「3. 导出与截图」按需打开「导出企业信息」或「截图并保存」（两者默认关闭），需要保存时再点击「选择文件夹」指定目录（可选）
5. 批量查询在「4. 执行」点击「开始」；单个查询已在第 2 步直接启动

运行过程中如需人工处理验证码或登录，请在**自动打开的那个标签页**里操作，处理完成后扩展会自动继续（最长等待 5 分钟）。

## 截图与命名规则

截图开关默认关闭，需要在「3. 导出与截图」中打开；关闭时只执行查询，日志会记录最终打开的详情页地址，不生成图片。

- 文件名：`企业名称_YYYYMMDD_HHmmss.png`
- 选定文件夹时：`<所选文件夹>\<站点>\企业名称_时间戳.png`
- 未选定或授权失效时：`下载\企业截图\<站点>\企业名称_时间戳.png`
- 站点子目录名固定为 `gsxt` / `企查查` / `爱企查`
- 同名文件不会被覆盖，会自动追加序号
- 查询结果中若有多家同名企业，默认取第一条

示例：

```text
截图\gsxt\某某科技有限公司_20260101_101500.png
截图\企查查\某某科技有限公司_20260101_101530.png
截图\爱企查\某某科技有限公司_20260101_101600.png
```

## 信息提取

在「3. 导出与截图」中勾选「导出企业信息」后生效（默认关闭）。生效时每次进入企业详情页都会提取下列固定字段，任务结束（含中途停止）后汇总成一个 Excel：

- 文件名：`企业信息提取_YYYYMMDD_HHmmss.xlsx`
- 位置：所选文件夹的**根目录**；未指定时保存到 `下载\企业截图\`
- 工作表「企业信息」：每个「企业 × 站点」一行，固定 **27 列**，顺序固定，页面没有的字段统一填 `-`：

  ```text
  企业名称  站点  统一社会信用代码  法定代表人  注册资本  成立日期  登记状态  企业类型
  注册地址  经营范围  详情页地址  所属行业  营业期限  登记机关  核准日期
  联系电话  电子邮箱  网址  行政区划  实缴资本  曾用名
  工商注册号  组织机构代码  纳税人识别号  纳税人资质  参保人数  分支机构参保人数
  ```

- `企业名称` 列使用导入时的名称，便于与原始名单对齐
- 同一企业同一站点重复执行时只保留最后一次结果

只提取上述字段，页面上的其它信息（股东、变更记录等）不会写入表格。字段识别规则在 `content/content.js` 的 `FIELD_LABELS` 中维护，每个字段可配多个别名，例如「住所」会归入「注册地址」、「经营者」归入「法定代表人」。表格支持两列与「标签 | 值 | 标签 | 值」的多列键值结构（爱企查工商注册信息即此结构）。

两点补充：

- 进入详情页后会**先滚动到底再回到顶部**，触发懒加载后再提取，确保靠后的区块也已渲染
- `统一社会信用代码` 若未被标签规则识别，会再按 18 位编码规则（字符集不含 I O S V Z）在标签附近匹配；取到的值不合法时宁可不写入，也不会把问号图标的提示文案当成编码

## 支持的站点

| 站点 | 顺序 | 是否需登录 | 注意事项 |
| --- | --- | --- | --- |
| [国家企业信用信息公示系统](https://www.gsxt.gov.cn) | 1 | 一般不需要 | 查询过程会整页跳转；验证码为 geetest 滑块 |
| [企查查](https://www.qcc.com) | 2 | 需要 | 未登录会跳转登录页；结果链接带 `target=_blank`，扩展在当前标签页内跳转 |
| [爱企查](https://aiqicha.baidu.com) | 3 | 必须登录 | 未登录时搜索结果会被重定向到登录页；结果条目是 SPA 的 JS 路由元素（非 `<a>`）；存在反调试检测 |

扩展复用浏览器中已有的登录状态，建议在开始任务前先手动登录好对应站点。

## 常见问题

**提示「需要登录，请在页面中完成登录…」**
在自动打开的标签页里手动登录即可，扩展检测到登录完成后会自动继续；也可提前在浏览器里登录好。

**提示「检测到验证码，等待人工验证…」**
在页面上手动完成滑块验证，通过后自动继续。超时未完成则本条记为失败，可用「重试失败」重跑。

**提示「站点拒绝访问：检测到浏览器调试状态」**
爱企查具有反调试检测，请关闭该标签页的开发者工具（F12）后重试；若仍然触发，可在「3. 截图设置」关闭截图开关，这样查询过程完全不接触调试接口。

**页面显示「当前IP请求异常，请更换IP地址进行访问」**
触发了站点的 IP 维度风控。建议减少单次批量数量、稍后再试，或更换网络环境。

**保存位置提示授权失效**
浏览器对文件夹写入的授权按会话有效，重新点一次「选择文件夹」即可；失效期间扩展会自动回退到下载目录，不会丢图。

**日志提示「请校准 content/sites.js」**
站点前端改版导致选择器失效，处理方式见下文「选择器校准」。

**运行时浏览器提示「正在调试此浏览器」**
截图通过 `chrome.debugger` 实现，属正常现象。被截图的标签页需保持打开状态；关闭「3. 截图设置」里的截图开关后不会再出现该提示。

## 实现要点

1. **编排逻辑放在侧边栏**：Manifest V3 的后台 Service Worker 会在空闲约 30 秒后被回收，把批量编排放在常驻的侧边栏页面中更可靠。
2. **轮询驱动状态**：查询过程会发生整页跳转、内容脚本随之重载，用面板轮询页面状态的方式天然兼容跳转。
3. **整页截图**：通过 `chrome.debugger` 的 CDP 接口，先把视口高度撑到整页高度再截图，单次生成完整长图。
4. **页面状态机**：每个页面被识别为 `home` / `results` / `detail` / `captcha` / `login` / `empty` / `debugblock` 之一，面板据此推进流程。

其他运行参数：

- 相邻两条任务之间随机间隔 3～8 秒，用于降低触发风控的概率
- 单条任务等待查询结果最长 40 秒
- 等待人工处理验证码或登录最长 5 分钟

## 选择器校准

站点前端改版后，通常只需修改 `content/sites.js`，无需改动 `content/content.js`。

每个站点的配置字段：

| 字段 | 含义 |
| --- | --- |
| `searchInput` | 搜索框选择器候选列表 |
| `searchButton` | 查询按钮选择器候选列表 |
| `resultLink` | 搜索结果条目选择器候选列表 |
| `detailUrlPattern` | 详情页 URL 特征（优先用它判断是否已进入详情页） |
| `resultsUrlPattern` | 结果页 URL 特征（限定结果页地址，避免误判） |
| `loginUrlPattern` | 登录页 URL 特征（未登录被重定向时用它判断） |
| `allowNonAnchorResult` | 结果条目不是 `<a>` 时，是否允许按企业名定位可点击元素 |
| `emptyHint` / `blockHint` | 无结果 / 被拦截页面的文案识别正则 |
| `detailText` | 详情页文案特征 |
| `loginDialog` | 登录弹窗选择器候选列表 |

**定位方法**：运行一次任务使其失败，日志会自动输出下列诊断信息，把后两行贴出即可定位问题。

```text
诊断：标签页地址 https://...（加载状态 complete）
诊断：[qcc] 标题「...」 地址 https://...
诊断·页面文本 → ...（页面可见文本样本）
诊断·同名元素 → tag=... class=... href=... 所在链接=... 文本=...
诊断·企业名结构 → <div class="...">...（企业名所在元素的真实 HTML）
诊断·输入框 → tag=input id=... class=... placeholder=... 可见=true
诊断·含关键词元素 → tag=button class=... 文本=查一下 可见=true
```

**维护建议**：

- 优先使用稳定、语义化的属性（`id`、`name`、URL 特征）而非纯样式类名
- URL 特征（`detailUrlPattern`、`resultsUrlPattern`）比文案匹配稳定得多，应优先补充
- SPA 场景下若页面上不存在真实的详情页链接，应开启 `allowNonAnchorResult`
